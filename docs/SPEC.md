# MiND SNiPER（連想スナイピングゲーム）仕様書

Nov 9, 2026 · @しんたろう

## 1. 概要と用語

ゲーム名は「連想スナイピングゲーム MiND SNiPER」。タイトル画面とロゴでは「MiND SNiPER」（iのみ小文字）と表記し、日本語の副題「連想スナイピングゲーム」を添える。副題は多言語化の対象とし、英字タイトルは全言語共通とする。標的が出す「遠い」連想ヒントから、狙撃手がお題を撃ち抜く、HP制の対戦型連想ゲーム。プレイ人数は3〜6人。1台のスマホを回して使うパス・アンド・プレイ方式のWebアプリとして実装し、サーバー・ログインは使わない。

| 用語 | 意味 |
| --- | --- |
| 標的（ターゲット） | そのラウンドの出題者。お題とヒント5つを作る |
| 観測手（スポッター） | そのラウンドの監督者。ヒントの承認・並べ替え、命中判定、端末操作を担う。常に1人 |
| 狙撃手（スナイパー） | 標的と観測手以外の全員。ヒントからお題を当てる |
| ラウンド | 1人の標的による1出題。命中または逃げ切りで終わる |
| ターン | 全員が1回ずつ標的を務めるまでのラウンドのまとまり（人数と同じ数のラウンド） |
| 射 | ヒント1つを公開して狙撃手が回答する1区切り。1ラウンドは最大5射 |
| 命中 | 狙撃手がお題を当てること。標的がダメージを受ける |
| 誤射 | 狙撃手が回答して外すこと。その狙撃手がダメージを受ける |
| パス | 狙撃手がその射で回答しないこと。ダメージなし |
| 逃げ切り | 5射終了まで命中が出ないこと。標的のHPが回復する |
| 脱落 | HPが0になること。その瞬間にゲームが終わる |
| 延長戦 | ターン数に達した時点で脱落者がおらず1位が同点のときに続けるラウンド。ダメージ倍率が上がる |
| サドンデス | 脱落者が出た時点で1位が同点のとき、同点者だけで行う決定戦 |

## 2. ゲームルール

本章の数値はすべて初期値で、CONFIGで変更できる（第4章）。

### 2.1 役割と輪番

- ゲーム開始時に登録したプレイヤーの並びを「席順」とする。
- 第rラウンド（0始まり）の標的は席順\[r mod n\]、観測手は席順\[(r+1) mod n\]。残り全員が狙撃手。
- 人数に関わらず観測手は1人。3人なら狙撃手は1人、6人なら4人。
- nラウンドで1ターン。ターン数に達したかの判定はターンの終わりに行う。

### 2.2 お題

- お題は物の名前（具体名詞・固有名詞）に限る。
- ラウンドごとに、標的が「任意出題」と「辞書からランダム出題」を選ぶ。辞書が1件もないときは任意出題のみ。
- 任意出題は自由入力（漢字・カタカナ等、表記は問わない）。判定は口頭で人が行うため、アプリは照合しない。
- ランダム出題は、まず有効なカテゴリを等確率で選び、その中から単語を選ぶ（2段階抽選）。同一ゲーム中に出た単語は除外。
- ランダム出題は、1ラウンドにつき引き直し上限回数（初期値1回）まで引き直せる。
- 標的と観測手は、お題を知らなければ調べてよい。狙撃手は回答時に調べてはならない（ルール説明に明記、アプリでの強制はしない）。

### 2.3 ヒントの作成と承認

1. 標的はお題から連想できるヒントを5つ作る。品詞は問わない。すべて遠いヒントでもよい。
2. 入力チェック：空欄不可、ヒント同士の重複不可、お題と同一の文字列不可。
3. 観測手は各ヒントが「普通の人の知識でお題を連想できるか」を判定する。調べて初めて繋がる知識は基準にしない。
4. 成立しないヒントは差し戻す。標的は差し戻されたヒントを書き換え、再び観測手の判定を受ける。回数制限なし。
5. 全ヒントが成立したら、観測手が遠い順に並べ替えて承認する。判断は相対比較でよい。
6. 承認された順に距離点 10・8・6・4・2 を割り振る。
7. その後、出題順をランダムにシャッフルする。出題順と距離点の対応はゲーム終了まで表示しない。

### 2.4 射撃の進行

- 射撃中は観測手が端末を持ち、公開済みヒントを全員に見せる。
- 狙撃手の回答順はラウンドごとにジャンケンで決め、観測手がアプリ上で並べ替えて登録する。初期の並びは席順で観測手の次の人から。
- 各射で、狙撃手は回答順に1人1回、口頭で回答するかパスする。
- 観測手はその狙撃手について「命中」「誤射」「パス」のいずれかを入力する。誤射時は回答内容を任意でメモでき、狙撃手ごとの誤射履歴として表示する。
- 命中の判定基準は「お題と同じものを指しているか」。標的と観測手の判断が割れたら、観測手の判定を最終とする。
- 命中が出た時点でラウンド終了（その射の残りの狙撃手は回答しない）。
- 5射目まで命中が出なければ逃げ切り。

### 2.5 ダメージと回復

- 全員HP100で開始し、上限は120。下限は0（マイナスにはしない）。
- 命中：標的に （回数点＋命中したヒントの距離点）× 倍率 のダメージ。回数点は1〜5射目で 50・40・30・20・10。通常時の最大は60。
- 誤射：その狙撃手に 5 × 倍率 のダメージ。
- 逃げ切り：標的のHPが20回復（上限120、倍率はかけない）。
- 倍率は通常・サドンデスで1倍、延長戦で2倍。
- パスにダメージはない。

### 2.6 秘匿

- 全員のHP、受けたダメージ量、回復量は、本人を含め誰にもゲーム中に表示しない。
- ラウンド終了時に表示するのは、お題、命中か逃げ切りか、命中した狙撃手と射番号まで。
- ヒントごとの距離点もゲーム終了まで非表示。
- ゲーム終了後に全記録を公開する（3.10）。

### 2.7 終了条件と勝敗

決着方式はCONFIGで「サドンデス方式（初期値）」と「引き分け方式」から選ぶ。

**共通**

- 誰かのHPが0になった瞬間（射の途中でも）、アプリがゲーム終了を告げる。誤射による脱落も含む。
- 脱落者以外で残りHPが最も多い人の勝ち。
- ターン数（初期値3ターン）に達し、1位が単独ならその人の勝ち。同点の扱いは決着方式による。

**サドンデス方式**

- ターン数に達した時点で脱落者がおらず1位が同点 → 延長戦。全員参加のまま、輪番を続け、誰かが脱落するまで続ける。倍率2倍。延長戦にターン数の上限はない。
- 脱落者が出た時点で1位が同点（延長戦中を含む）→ サドンデス。
- サドンデスの参加者は1位の同点者のみ。観測手は直前の脱落者が務める。
- 標的の順番はジャンケンで決め、観測手がアプリに登録する。サドンデス中に参加者のHPが0になった瞬間、サドンデス終了。残りの参加者のうちHPが最も多い人の勝ち。残りの1位が同点なら、その同点者だけで再びサドンデスを行い、観測手は今回HP0になった人が務める（本戦と同じ仕組みの繰り返し）。
- HPが0になる人が出ないまま参加者全員が1回ずつ標的を務めた場合は、その時点のHPで比較し、最多の人の勝ち。それでも同点なら、同点者だけでサドンデスを繰り返す（観測手は同じ人）。HPは常に前の値を引き継ぐ。
- 同点者が2人の場合は、どちらかのHPが0になった瞬間にもう一方の勝ちで決着する。

**引き分け方式**

- 延長戦もサドンデスも行わない。1位が同点ならその全員の引き分け。

## 3. 画面仕様

秘密情報（お題・ヒント・HP）を扱う画面の前には必ず「受け渡し画面」を挟む。スマホ縦持ち・片手操作を前提とする。

### 3.1 共通：受け渡し画面とセーフティ

- 受け渡し画面は「○○さん（観測手）に端末を渡してください」と役割名・プレイヤー名を表示し、秘密情報は一切表示しない。
- 秘密情報を開くボタンは長押し（初期値1.5秒）で発動する。通常のタップでは開かない。押している間は進捗ゲージを表示する。
- 秘密情報の画面を閉じると、次の受け渡し画面に自動で移る。
- ゲーム中は画面スリープを防ぐ（Wake Lock API、非対応端末では無視）。
- ゲーム中の「中断してトップへ」は確認ダイアログを出す。状態は保存されているので後から再開できる。

### 3.2 トップ

- ボタン：新規ゲーム、続きから（保存データがあるときのみ）、ルール説明、CONFIG。
- 未完了のゲームが保存されている状態でアプリを開いたら、「続きから始める／新規ゲームを始める」の選択ダイアログを出す。新規を選んだ場合は「保存中のゲームは削除されます」と再確認する。
- 続きから再開するときは、秘密情報を含む画面に直接戻らず、必ずその場面の受け渡し画面から再開する。

### 3.3 プレイヤー登録

- 人数（3〜6）を選び、人数分の名前を入力する。空欄・重複は不可。前回の名前を初期入力として複製してよい。
- 並べ替え（ドラッグまたは上下ボタン）で席順を決める。「ランダムに並べる」ボタンも置く。
- 決定すると、その時点のCONFIGをゲームに固定して第1ラウンドへ進む。

### 3.4 ラウンド開始

- ターン・ラウンド番号、延長戦／サドンデスの別、標的・観測手・狙撃手の名前を全員に表示する。
- 「標的に端末を渡してください」へ進む。

### 3.5 出題（標的）

1. 出題方式を選ぶ：任意出題／ランダム出題。
2. 任意ならお題を入力。ランダムなら抽選結果とそのカテゴリを表示し、引き直しボタン（残り回数表示）を置く。
3. ヒント入力欄を5つ表示。入力順は自由で、遠さの順に並べる必要はない。
4. 「確定」で入力チェック（2.3）を行い、「観測手に端末を渡してください」へ。
5. 差し戻し時は、差し戻されたヒントだけが編集可能な状態で表示し、観測手のコメント（任意）を添える。

### 3.6 承認（観測手）

1. お題と5つのヒントを表示する。
2. 各ヒントに「差し戻し」チェックと任意コメント欄。チェックが1つでもあれば「差し戻す」で標的へ戻る。
3. 差し戻しがなければ、ヒントを遠い順（上が最も遠い）に並べ替え、「承認」。各行に割り振られる距離点を並べ替え中に表示する。
4. 承認後、狙撃手の回答順を登録する画面へ（ジャンケンの結果を並べ替えで入力）。この画面には秘密情報を表示しない。狙撃手が1人のときはこの画面を省略する。
5. 「射撃開始」で出題順をシャッフルし、射撃画面へ。

### 3.7 射撃（観測手が操作し、全員に見せる）

- 表示：射番号（1/5〜5/5）、公開済みヒント一覧（公開順、最新を強調）、今回答する狙撃手の名前、狙撃手ごとの回答履歴（誤射とそのメモ、パスを「3射目【パス】」のように射番号つきで残す）。
- 操作：現在の狙撃手に対して「命中」「誤射」「パス」。誤射時は回答メモの入力欄（空欄可）を出す。
- 「命中」は確認ダイアログを挟む（誤タップ防止）。
- 直前の1操作を取り消せる「元に戻す」を置く。ただし脱落が発生した操作は確定後に取り消せない。
- 「お題を確認」ボタン：長押しでお題を表示し、指を離すと消える。観測手が判定で迷ったとき用。
- 各射で全狙撃手の入力が終わったら次の射へ。誤射で狙撃手のHPが0になったら、その場で終了判定（3.9）へ。
- ヒントの距離点、HP、ダメージ量は表示しない。

### 3.8 ラウンド結果

- お題、命中（狙撃手名と射番号）または逃げ切りを表示する。数値は表示しない。
- 次のラウンド、延長戦突入、または終了へ進む。

### 3.9 終了判定と告知

- 脱落発生時：「脱落者が出ました。ゲーム終了」と脱落者名を表示。
- 延長戦突入時：「延長戦：ダメージ2倍」を告知。誰が同点かは示さない。
- サドンデス突入時：参加者（同点者）と観測手（脱落者）を告知し、ジャンケンで決めた標的の順を入力する画面へ。HPの値は示さない。
- それ以外の終了時：結果発表へ。

### 3.10 結果発表

- 順位と最終HPを発表する。引き分けはその旨を表示。
- 全ラウンドの記録：標的・観測手、お題、ヒント（出題順）と各距離点、命中した射と狙撃手、ダメージ量、誤射とそのメモ、パス、回復。
- プレイヤーごとのHP推移を折れ線グラフで表示する。
- 「同じメンバーでもう一度」（同じ名前と席順を入力済みの状態でプレイヤー登録画面を開く）「トップへ」ボタン。終了したゲームの保存データは、次のゲーム開始時に削除する。

### 3.11 ルール説明

- トップとゲーム中メニューから開ける。ゲーム中に開いても秘密情報は表示しない。
- 内容：遊び方の概要、役割、進行、ダメージと回復、勝敗（延長戦・サドンデス）、禁止事項（狙撃手は調べない）。
- 数値は現在のCONFIG値を差し込んで表示する。

### 3.12 CONFIG

- 第4章の全項目を編集できる。入力値は範囲チェックし、範囲外は保存しない。
- 「デフォルトに戻す」ボタン（確認あり）。
- ゲーム中に開いた場合は「変更は次のゲームから反映」と表示する。
- 言語切替え欄を置く（初期は日本語のみ）。
- 辞書のカテゴリごとの有効／無効を切り替えられる。

## 4. CONFIGパラメータ

すべての調整値は1つの設定オブジェクトにまとめ、コード内に数値を直書きしない。ゲーム開始時の値をそのゲームに固定する。

| 項目 | 初期値 | 範囲・形式 |
| --- | --- | --- |
| 開始HP | 100 | 10〜999 |
| 上限HP | 120 | 開始HP以上 |
| 回数点（1〜5射目） | 50, 40, 30, 20, 10 | 非負の整数5つ、狭義の降順 |
| 距離点（遠い順） | 10, 8, 6, 4, 2 | 非負の整数5つ、狭義の降順 |
| 誤射ダメージ | 5 | 0〜99 |
| 逃げ切り回復量 | 20 | 0〜99 |
| ターン数 | 3ターン | 1〜10 |
| 延長戦のダメージ倍率 | 2 | 1〜5（命中・誤射に適用） |
| サドンデスのダメージ倍率 | 1 | 1〜5（命中・誤射に適用） |
| 決着方式 | サドンデス | サドンデス／引き分け |
| ランダム出題の引き直し回数 | 1 | 0〜5（ラウンドあたり） |
| 秘密情報ボタンの長押し時間 | 1.5秒 | 0.5〜5秒 |
| 辞書カテゴリの有効・無効 | すべて有効 | カテゴリごと |
| 表示言語 | 日本語 | 登録済み言語 |

ヒント数は5固定とする。ただし回数点・距離点を配列で持ち、配列長からヒント数を求める実装にして、将来の可変化に備える。

設計上の制約：回数点の隣り合う差は、距離点の最大差（最大値−最小値）より大きくする。これを破ると「わかっていてもわざとパスして遠いヒントを待つ」戦法が得になる。CONFIG画面でこの条件を満たさない値を入れた場合は警告を表示する（保存は可能）。

## 5. データ仕様

### 5.1 辞書

今回は辞書の「箱」（形式、読み込み、抽選）だけを作る。中身はシステム完成後に別途作成する。

- 配置：`public/dictionaries/` 配下のJSONファイル。`index.json` に辞書ファイル名の一覧を置き、アプリはそれを起点に読み込む。ファイルを足すだけで辞書を追加できる。
- 言語：辞書ファイルは `lang` を持ち、表示言語と一致するものだけを使う。
- 動作確認用に、各カテゴリ数件のサンプル辞書を同梱する。本番辞書で置き換える前提。
- 読み込み時に形式を検証し、不正な項目は除外してコンソールに警告を出す。有効な単語が0件ならランダム出題を無効にする。

辞書ファイルの形式：

```json
{
  "version": 1,
  "lang": "ja",
  "name": "基本辞書",
  "categories": [
    { "id": "prefecture", "label": "都道府県" }
  ],
  "entries": [
    {
      "id": "pref-hokkaido",
      "word": "北海道",
      "reading": "ほっかいどう",
      "category": "prefecture",
      "year": 2026
    }
  ]
}
```

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| id | 必須 | 辞書内で一意のID |
| word | 必須 | 表示するお題 |
| reading | 任意 | 読み。標的・観測手への表示に使う |
| category | 必須 | categories の id |
| year | 任意 | 収録年。時事性のある人名などの更新管理用 |

将来の辞書の収録方針（参考、今回の実装対象外）：物の名前に限る。日本の学校で習う歴史上の人物、都道府県、県庁所在地、有名な地名、海域、山（日本の高い山と有名な山、世界は地理で習う程度）、河川（日本は長さと流域面積それぞれ上位10程度、世界は地理で習う程度）、国名、世界の首都、小中学校程度の具体名詞、日本人なら誰でも知る芸能人、ここ数年よく見る芸能人と政治家（総理大臣・国務大臣級）。抽象名詞は含めない。

### 5.2 保存

- 保存先はブラウザの localStorage。サーバー・ログイン・Cookieは使わない。
- 保存するもの：進行中のゲーム状態、CONFIG、前回のプレイヤー名、表示言語。キーはアプリ固有の接頭辞を付ける。
- ゲーム状態は操作のたびに保存し、再読み込みや誤って閉じた場合も直前の状態から再開できる。
- 保存データにはスキーマのバージョン番号を持たせる。読めない古いデータは破棄し、その旨を表示する。
- ゲーム状態には、画面の位置（どの場面か）、各プレイヤーのHP、全ラウンドの記録、使用済みのお題、ゲームに固定したCONFIGを含める。
- 注意書き（ルール説明に記載）：同じ端末・同じブラウザでのみ再開できる。プライベートモードや履歴の削除では消える。

## 6. 技術仕様

サーバーを持たない静的サイト（SPA）として作り、GitHubからVercelへ自動デプロイする。

| 分野 | 採用 |
| --- | --- |
| ビルド・言語 | Vite + React + TypeScript（strict） |
| 状態管理 | ゲーム進行は useReducer による状態機械。アクションごとに localStorage へ保存 |
| 画面遷移 | ゲーム内は状態機械の場面で切り替える（URLに秘密情報を含めない）。トップ・ルール・CONFIGはルーティング |
| 多言語 | react-i18next。画面の文言はすべて `src/locales/<lang>.json` に置き、コードに直書きしない。初期は ja のみ |
| スタイル | スマホ縦持ち優先。ライト／ダークモード対応。ボタンは片手で押せる大きさ |
| PWA | vite-plugin-pwa。ホーム画面への追加、全画面表示、オフライン動作（辞書もキャッシュ） |
| グラフ | 結果発表のHP推移に軽量なグラフライブラリまたは自前SVG |
| テスト | Vitest。ダメージ計算、輪番、終了判定、延長戦・サドンデスの遷移、辞書抽選を単体テストする |
| デプロイ | GitHubリポジトリをVercelに接続。mainへのpushで本番、プルリクエストでプレビュー。SPAのため全パスを index.html に書き換える設定を入れる |

実装の構成方針：

- ゲームロジック（輪番、ダメージ計算、終了判定、シャッフル、抽選）は画面から切り離した純粋関数にし、テストできるようにする。
- 乱数は差し替え可能にし、テストでは固定値を使う。
- プレイヤーは名前でなく内部IDで管理する。
- 開発時のみ、全HPと距離点を表示するデバッグ表示を用意する（本番ビルドでは無効）。

## 7. 試遊で調整する項目と実装上の注意

試遊で調整する前提の項目（いずれもCONFIGで変更可能）：誤射ダメージ、逃げ切り回復量、ターン数、延長戦の倍率、回数点と距離点の配分。

実装上の注意：

- **秘匿の徹底**：HP・ダメージ量・距離点は、結果発表までどの画面にも出さない。演出（アニメーションの長さ、色、音）もダメージ量や距離点で変えない。変えると値が推測できてしまう。
- **告知による情報漏れは仕様として許容する**：延長戦突入は「1位が同点」を、サドンデス突入は「同点者が誰か」を明かす。値そのものは示さない。
- **延長戦突入の判定タイミング**：最後のターンの最終ラウンドが終わった時点。途中で脱落が出たらそちらが優先。
- **localStorageの中身**：開発者ツールを開けばHPは見える。対面のパーティーゲームとして許容し、暗号化はしない。
- **狙撃手が調べないこと**：アプリでは強制できないため、ルール説明で明示する。
- **将来の辞書作成**：AIで収集する場合、5.1の収録方針と形式に従う。芸能人・政治家など時事性のある項目はWeb検索で最新性を確認し、year を入れる。
